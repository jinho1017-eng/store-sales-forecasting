# Store Sales 시계열 예측 (매장·상품군별 판매량 예측)

**Kaggle Store Sales - Time Series Forecasting** 대회를 기반으로, 7일간(하루 약 3시간) 데이터 분석부터 머신러닝 모델링, 검증, 제출까지 전 과정을 직접 진행한 프로젝트입니다.

- **대회 링크:** https://www.kaggle.com/competitions/store-sales-time-series-forecasting
- **노트북:** [Store Sales Forecasting - EDA, Baseline & LightGBM](https://www.kaggle.com/code/kjinho/store-sales-forecasting-eda-baseline-lightgbm)
- **평가 지표:** RMSLE (Root Mean Squared Logarithmic Error, 낮을수록 좋음)

---

## 1. 문제 정의

에콰도르의 대형 슈퍼마켓 체인(Corporación Favorita)의 **날짜 × 매장 × 상품군**별 판매량을 예측합니다.

- **예측 대상:** `sales` (판매량, 소수 가능 — 무게 단위 상품 때문)
- **예측 기간:** 2017-08-16 ~ 2017-08-31 (**16일**. 대회 설명에는 "15 days"라고 적혀 있으나, 실제 데이터로 확인한 결과 16일이었음)
- **단위:** 54개 매장 × 33개 상품군 조합마다 하루씩 예측 (test 28,512행 = 16일 × 54 × 33)
- **제출 형식:** `id,sales` (헤더 포함), 정수 반올림 금지

## 2. 데이터

| 파일 | 내용 |
|---|---|
| `train.csv` | 2013-01-01 ~ 2017-08-15, 3,000,888행. 날짜·매장·상품군·판매량·프로모션 |
| `test.csv` | 예측 대상 16일, 28,512행 (정답 없음, `onpromotion`은 미리 주어짐) |
| `stores.csv` | 매장 54개의 도시·주·유형·클러스터 |
| `holidays_events.csv` | 휴일·행사 (전국/지역/도시 범위, 대체 휴일 여부 포함) |
| `oil.csv`, `transactions.csv` | 참고용 보조 데이터. `transactions`는 test 기간 값이 없어(미래 정보) 직접 변수로 사용하지 않음 |

**데이터 품질 확인 사항**
- 결측치·중복 없음
- 매년 12월 25일(2013~2016) 4일치 기록이 통째로 없음 (휴무 추정, 0으로 채우지 않음)
- 판매량 0이 전체의 31.3% — 그중 약 9.5%만 "완전히 안 파는 조합"(53개)으로 설명되고, 나머지는 **2015년 중반 이전 판매 기록 자체가 불안정**했기 때문으로 추정 (월별 0 비율 그래프로 확인)
- 상품군 간 판매 규모가 최대 **약 18,500배** 차이 (매장당 하루 평균: GROCERY I 4,619.7 ~ BABY CARE 0.25)

## 3. 검증 방식

**무작위로 데이터를 섞지 않고, 시간 순서를 지키는 시계열 검증**을 직접 구성했습니다.

- train 끝부분에서 **test와 같은 길이(16일)의 구간 3개**를 연속으로 분리
  - **Fold1** (개발용): 2017-06-29 ~ 07-14
  - **Fold2** (개발용): 2017-07-15 ~ 07-30
  - **Holdout** (최종 확인 전용): 2017-07-31 ~ 08-15 — 모델 선택이 끝날 때까지 점수를 보지 않고 아껴둠
- 각 구간은 **구간 시작일 이전 정보만** 사용 (미래 정보 완전 차단)
- 통계 변수(최근 평균 등)는 **예측 구간 전체에 고정값으로 적용** — 행별로 재계산하지 않아, 16일 중간에 실제 판매량이 섞여 들어가는 누출을 방지
- 자체 구현한 `rmsle()` 채점 함수를 실제 캐글 점수와 대조해 신뢰도 확인 (기준 모델 기준 자체 검증 평균 0.4336 vs 실제 캐글 0.4449, 약 0.011 차이)

## 4. 모델 비교

| 모델 | 설명 | Fold1 | Fold2 | Holdout | 평균(F1,F2) | 실제 캐글 |
|---|---|---|---|---|---|---|
| **기준 모델** | 매장×상품군별 최근 4주 같은 요일 평균 | 0.4245 | 0.4427 | 0.5311 | 0.4336 | **0.44491** |
| **LightGBM (기본 변수)** | 날짜·요일·매장·상품군·프로모션 | 0.4612 | 0.4622 | — | 0.4617 | 0.46731 |
| **LightGBM + 과거 판매량 요약** (최종 제출) | 기본 변수 + 매장×상품군별 최근 4/8/12주 평균, 최근 같은 요일 평균 (학습 행은 날짜별 rolling, 예측 구간은 고정 통계로 누출 방지) | **0.3814** | **0.3952** | **0.4291** | **0.3883** | 0.46605 |

**추가로 시도했지만 채택하지 않은 변수/설정**

| 시도 | 결과 |
|---|---|
| 매장 특성 추가 (도시·주·유형·클러스터) | 개선 없음 (0.3908). `store_nbr`와 중복 정보라 새로운 정보를 주지 못함 |
| 휴일 변수 추가 | 거의 효과 없음 (0.3886). 검증 구간(6~7월)에 휴일이 너무 적어(864개 중 4~17개) 테스트 자체가 어려웠음 |
| `num_leaves` 31→63 | 전체 점수 변화 없음, 오히려 프로모션 관련 과소예측이 악화되어 기각 |

**최종 선택: LightGBM + 과거 판매량 요약**
내부 검증 3개 구간(Fold1, Fold2, Holdout) 모두에서 기준 모델보다 우수했기 때문에, "모델 선택은 자체 검증을 중심으로 한다"는 원칙에 따라 이 모델을 최종으로 선택했습니다.

| 항목 | 값 |

## 6. 한계

- **실제 캐글 점수는 자체 검증 결과와 반대로, 기준 모델이 LightGBM보다 좋았습니다.** 오류 분석 결과, LightGBM이 **프로모션이 있는 날 판매량을 4~7배 더 심하게 과소예측**하는 경향을 확인했고, 검증에 사용한 구간(6~7월)과 실제 test 기간(8월 중순) 사이의 계절적 차이가 원인으로 의심되나 완전히 규명하지는 못했습니다.
- 내부 검증 구간이 3개뿐이라 표본이 적습니다. Holdout 구간에서는 기준 모델조차 평소보다 크게 나빠져(0.53), 검증 구간 자체의 변동성이 작지 않다는 것을 보여줍니다.
- 상품군 33개의 판매 규모가 최대 18,500배 차이 나는데, **모델 하나로 전체를 학습**했습니다. 상품군별로 모델을 분리하면 개선 여지가 있습니다.
- 변수 설계가 단순합니다 (lag 변수, 연간 계절성(Fourier) 변수, 앙상블, 자동 하이퍼파라미터 탐색 등은 포함하지 않음 — 7일 일정의 범위를 벗어나 후속 과제로 남겨둠).
- 재고 데이터가 없어 **재고 비용 절감 효과는 측정하지 않았습니다.**

## 7. 실행 방법

1. [Kaggle 노트북](https://www.kaggle.com/code/kjinho/store-sales-forecasting-eda-baseline-lightgbm)을 엽니다.
2. **Edit** → **Run** → **Run all**을 클릭하면, 데이터 로딩부터 분석·검증·학습·제출 파일 생성까지 전체가 처음부터 재현됩니다 (CPU 기준 약 5~10분).
3. 별도 설치가 필요한 라이브러리는 없습니다 (`pandas`, `numpy`, `lightgbm`은 Kaggle 환경에 기본 포함).
4. 노트북 실행 후 `/kaggle/working/submission.csv`가 생성되며, **Output** 탭에서 **Submit to Competition**으로 바로 제출할 수 있습니다.
